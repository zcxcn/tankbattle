# PC 0.4.14 — 主菜单选车卡顿修复

## 现象与原因

用户在主菜单切换坦克时感到明显卡顿。`cycle_chassis()` 原先调用 `_show_title_tank()`；后者会销毁并重建整张任务地图、天气、装饰、展示坦克和标题镜头。选车只需更换展示坦克，却在主线程重复建图。

## 改动

- 保留当前地图、天气和标题镜头；选车时仅释放旧展示坦克并实例化所选车型。
- 进入战役、切换关卡、返回菜单仍沿用原有完整场景流程。
- 新增真实主菜单调用链回归测试，检查三次选车、地图和镜头身份不变、始终只有一辆展示坦克，以及选车后开战和返回菜单。

## 验证

- 同一台机器、Godot 4.7.2、无图形后端的生产主场景测试：修复前连续三次选车分别耗时 **1118、1089、926 ms**；修复后为 **169、214、8 ms**。这些是同步主线程调用耗时，不代表完整渲染帧率。
- `title_selection_test.gd` 通过；手柄回归 **43/43**，天气设置回归 **52/52**。
- Windows 0.4.14 Release 包通过构建脚本的结构、哈希、版本元数据、ZIP 和启动检查；输出 `outputs/pc-godot/Iron-Embers-Windows-x86_64-0.4.14.zip`。
- 新版 EXE 已在本机启动，窗口随后保持 `Responding=True`。Windows 图形捕获接口返回 `SetIsBorderRequired failed: 不支持此接口 (0x80004002)`，因此这次没有可核验的前台截图或远程桌面帧率数据。用户的实际远程桌面流畅度仍需试玩确认。
