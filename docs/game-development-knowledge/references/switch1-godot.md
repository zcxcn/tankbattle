# Switch 1：Godot 3D 移植经验

适用于已有 Godot 游戏与 Switch homebrew 环境。2026-09-13 在 Tankbattle 的 Switch 0.1.0 中验证：使用 Stary2001 `v3.5.1-stable_switch_fixed` 的配套编辑器和 NRO 模板，导入、桌面实景渲染、战斗调用链及 NRO/PCK 静态校验可完成。真机性能与系统事件另行验证；不要继承其他项目的主机运行回执。

## 先核对运行时，再选择移植规模

Godot 4 的 Forward+、场景格式和脚本 API 不能直接交给此 Godot 3.5.1 模板。大型项目应隔离目标工程，复用有许可的源 GLB、纹理、音频及可转换的玩法数据；明确记录重新适配的渲染和功能差异，不宣称完全等效。C++ / libnx 并非所有 Switch 自制游戏的唯一实现路径。

从实际发行归档核验配套编辑器与模板的版本、长度、SHA256。运行时原生段应与所选模板一致；本地 pin 是复现依据，不等于上游数字签名。不要重复下载本机已经核验的同一归档，也不要修改其他项目的便携编辑器数据目录。

## 导入、资源与旧 API

- 按目标资源类型筛选复用文件。GLB 能导入不表示同目录的 Godot 4 `.tscn` 也能加载。引擎生成的 `.material` 可能是 `RSRC` 二进制；检查文件头或用引擎 API 读取，避免当文本整篇打印。
- `.import` 的纹理重复、过滤和 mipmap 默认值会影响大面积地表；坐标超出 0–1 时若纹理被夹取，可能形成长条拉伸。实景检查后按材质用途设置，不给 UI 或动画图集统一启用 repeat。
- 使用目标引擎实际支持的 API。此 3.5.1 运行时使用 `OS.set_window_title()`；支持 `Image.save_png()`，没有 `Image.save_jpg()`。若平台要求 JPEG 图标，另用已验证的转换器，并检查 256×256 RGB baseline JPEG。
- 旧 Windows GUI 编辑器通过普通 PowerShell 调用时，本次出现日志为空；Python 子进程显式重定向后获得完整输出。脚本错误未必使进程退出，因此监测日志中的脚本/解析错误、设置超时并终止自己的失败进程，避免空等。

## 输入和证据边界

此固定版本的 Switch 后端将 B/A/Y/X 映射为 Godot 按钮 0/1/2/3，L/R/ZL/ZR 为 4/5/6/7，−/+ 为 10/11，方向键为 12–15，双摇杆轴为 0–3。其他运行时必须重新检查映射。

输入事件与轮询应遵循同一按钮状态语义。本次波次菜单测试通过真实 `InputEventJoypadButton` 路径暴露了仅轮询的模拟输入差异；消费事件状态并刷新输入缓冲后，同一路径可连续进入下一波。不能只直接调用“下一波”证明手柄菜单有效。

上游是否发出连接/焦点事件与游戏是否处理事件是两层证据。注入通知后暂停成功，不能证明按 HOME 或断开手柄时主机一定发送该通知；需要主机测试或检查并修改对应平台后端。

分开验证编辑器内项目、实际导出的 PCK、NRO 结构、MTP 读回和主机启动。NRO 与同名 PCK 必须保持相邻；只检查编辑器源项目或上传 NRO 都不构成完整交付。HOME 入口还需正确的固定 NRO 路径及项目独立 TitleID。
