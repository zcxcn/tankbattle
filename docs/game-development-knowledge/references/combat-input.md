# 战斗、反馈与输入

## 射击沿同一条真实链路

输入/AI决策 → 冷却与弹药检查 → 武器实际枪口变换 → 投射物 → 碰撞/爆炸 → 伤害事件 → 画面/声音/镜头反馈。避免视觉枪口、弹道起点和伤害方向各算一套。

高速弹丸需要连续碰撞、扫掠或等价查询；不能只检查每帧终点。验证近距离枪口遮挡、斜坡仰角、不同高度目标、远处命中及爆炸遮挡。侧置发射筒若始终平行发射，可能越过准星两侧；检查真实筒口会聚与转角限制，而不是扩大伤害来掩盖偏差。

“射程不够”分别检查发现距离、可见性、瞄准门槛、车体稳定条件、弹丸寿命/速度和实际碰撞。测试应让真实 AI 自己开火并命中，不能只把射程参数调大或强制调用发射接口。

## 敌人行为与可玩的节奏

初次发现范围、已发现目标的跟踪范围、理想机动距离是三种不同参数。把它们一起拉大，可能导致敌人很远就开火，却一直原地装填。

一种可用的载具节奏是装填间隙推进/调整位置，接近就绪时停车、获得连续瞄准时间，再开火。其他类型角色是否移动射击由玩法决定。同时观察敌人实际位移与开火，不用单个状态名证明追击正常。

失去视线后保存最后观察位置，搜索到期恢复巡逻；不要读取隐藏玩家当前位置来导航或提前瞄准。受到攻击可以搜索来弹方向，但伤害事件不应自动提供精确射手坐标。暂停、EMP、遮挡和目标失效要中断或冻结相应计时。

Boss 的威胁来自可读的攻击模式，不只是更高伤害。预警时锁定范围/落点，给躲避与恢复窗口；阶段变化不能在同一已预告攻击中突然扩大规模。检查同时叠加主炮、齐射和增援是否消除了玩家反应空间。

## 视听反馈

炮击可分为短促闪光、火焰喷射、后坐与复进、尘土/气浪和尾音；爆炸可分为早期闪光、冲击、碎屑、扩散烟尘和余火。不同阶段的速度、方向和衰减不同，避免整团粒子等速球形扩散。殉爆应有独立强烈事件与概率，同时控制重复伤害与持续特效数量。

被摧毁对象先失去作战能力，再进入倒地/残骸/燃烧/淡出流程；保留战斗结果和尸体生命周期的边界，不直接消失，也不让尸体继续阻止清场。

发射声不明显时依次检查事件触发、音频总线、距离衰减、声部被回收、响度与设备输出。机枪限制自身尾音声部时，不应误停炮声。履带、转向、撞击跟实际速度/角速度/接触事件变化；静止、暂停和销毁时结束循环。

专业感语音优先选许可清楚、表达简短的人声录音，用播报队列、冷却和优先级防止刷屏。可借鉴 RTS 的信息节奏，但不默认取得商业游戏音频使用权。Dummy 音频测试证明调用链，不能证明扬声器上确实听得见。

## 镜头、远程桌面和手柄

第三人称同时明确“鼠标控制准星还是镜头”“枪管指向哪里”“镜头受遮挡如何缩近”。切视角时同步指针模式、旧鼠标采样与相机混合状态，避免准星/镜头/发射方向分离。

远程桌面可能可靠传递绝对光标，却不能可靠提供捕获后的相对位移。保留可切换的绝对鼠标方案，并测试屏幕边缘、重新连接、窗口失焦与视角切换；不能用俯视鼠标正常来证明第三人称输入正常。

手柄覆盖实际设备事件、死区、扳机、焦点导航、断连时清除按住状态，以及重连后不自动恢复战斗。新增菜单入口后，检查方向键/摇杆重复导航的实际顺序；旧测试可能仍按原按钮数量移动，误点新功能后引发连锁失败。
