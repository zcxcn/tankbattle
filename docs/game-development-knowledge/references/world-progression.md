# 世界、导航与进度

## 可驾驶的世界先有共同坐标契约

连续地形用同一个高度定义生成可见网格、碰撞、出生点、巡逻点、目标与补给位置。法线、坡度和网格拼接处都要检查；只把视觉山丘摆在平面碰撞上不算可玩丘陵。

角色前方的低位射线会命中上坡地面。将可行走坡面的法线与角色坡度阈值比较，别把缓坡当墙绕行。用真实角色从坡脚开到坡顶再下坡，检查是否卡住、掉落、悬空及相机是否穿地。

河流保持水面、河床、岸坡和桥面各自的职责。视觉水面不应凭空形成可走平面；桥梁通道要留全车宽度和前后转弯净空。导航先对准桥口、沿桥轴跨越、等车尾离岸再拐弯，不能只把目标设在对岸后直线切过护栏。

道路与出生净空验证使用完整角色包围体，而不是单点射线。怪物体积增大后同时检查桥宽、出生区、路径转角、近战触达与死亡占地；根节点走到目标中心通常不是大体型近战的正确判定。

装饰材质与可玩地表分开作用。例如土路着色不应延伸到远景山体，背景地面应覆盖相机可见范围；雨雪材质副本也要接收当前天气参数，并在天气改变时更新，避免每帧重复写同一状态。

## “第一波后没下一波”的诊断树

先记录：游戏模式、当前波次、在场活体、待生成队列、生成失败原因、波次时钟、人口上限、暂停状态和下次事件。区分下面几种情况：

- 活体还有遗漏：按活体状态判断，排除尸体与待清理节点；检查敌人卡在边界或隐藏位置。
- 队列有任务却没生成：检查入口净空、随机候选、人口上限和资源加载。安排有界重试或合规备用点，避免无限循环及穿入障碍物强行生成。
- 活体和待生成均为空：确认推进只安排一次，延迟/暂停恢复后仍能执行。
- 时钟达到条件却不推进：检查实际主循环和调度器是否仍在运行，是否被 UI、模式切换或失焦暂停阻断。

“清场”通常要求活体为零且待生成队列为空；源源不断增援的模式还可能按时推进未清场波次。两种规则分开定义，不让待生成队列被错误当作已完成，也不要在每帧不断重置下一波倒计时。

回归需走正常游戏循环自然续波，并覆盖暂停恢复、入口全部占用、人口上限和重试。手动调用下一波函数只能检查单次生成，不能证明自动推进正常。

## 关卡、奖励与存档

波次调度、角色生命周期和 UI 快照分别负责自己的状态。死亡奖励、通关结算、解锁应幂等：重复死亡信号、终局后迟到事件、重复结算和重玩不能重复发奖。

局内武器成长、长期战役进度、最高纪录、设备设置分开保存。新模式的失败/重试不污染其他模式；切模式时清理活体、尸体、投射物、特效、调度器和临时升级。

增加关卡时同步检查目录总数、选择入口、下一关、终关判断、解锁连续性与测试中的固定上限。需要直接体验新地图时提供明确入口，不通过伪造旧关卡通关记录来解锁。最后验证真实 UI 到关卡构建的整条路径。
