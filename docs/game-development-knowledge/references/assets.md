# 资产与渲染

## 下载前先看能否用于游戏

核查原作者、具体资产页面、所选许可、贴图、骨骼、动作、几何规模和下载依赖。贴图标称 1K 不代表几何也小；一个“1K 模型”的二进制仍可能接近 GB。先读清单再下载，避免把大量时间用在并不适合实时渲染的原始资产上。

保留来源、许可文本/链接、下载时间、原始文件校验值和改造说明。不要把“免费下载”当作可重新分发；第三方署名应进入实际发行包。素材包的新修订可能替换受限贴图，检查当前包内文件而不是复制旧署名假设。

下载失败时区分认证、超时、损坏与吞吐量低；分段下载仅在服务器确实支持 Range 时使用，校验每段 Content-Range、长度和合并后的完整哈希。不要无限重试，也不要把工作用大文件自动提交到仓库。

## 模型导入的易错环节

1. 对外部 `.blend` 禁用自动脚本执行；用自有转换脚本显式读取目标对象。先打印对象、材质、贴图、骨骼和动作清单，旧文件可能停在 Pose 模式或隐藏集合里。
2. 统一项目约定的单位、朝向、脚底/轮底与根节点位置。不存在必须“全部归一到 1 米”的通用规则；检查变换矩阵和引擎实景中的尺度。怪物变大时同步检查碰撞、相机仰角、攻击距离、生成净空和尸体占地。
3. 保留每个 surface 的原始 PBR 材质、UV 和法线，区分 roughness 与 gloss。一个统一覆盖材质可能抹掉整套真实细节；附加 tint 应作用于原材质。
4. 清除非运行所需的相机、灯光和控制网格时，保留变形骨架、蒙皮绑定和仍需烘焙的约束。不要误删 IK 依赖。
5. 实际遇到过旧动作在较新 Blender 中需要明确指定 action slot、导出动作名改变、未应用 Mirror 导致只剩半身等问题。它们是版本相关排查项；先观察当前文件和导出结果，不能盲套 API 或应用所有修改器。
6. 导入后的图片、`.import`、`.uid` 可能是运行依赖；可再生缓存与源资源分开判断，不能把 GLB 导出到资源目录的贴图当垃圾删掉。

## 验证模型，而不只验证加载成功

在游戏引擎中检查正面、侧面、背面、近景和远景，放一个玩家或建筑作尺度参照。动画要检查骨骼确实随时间变化、接地位置和关键姿势；死亡要检查所有网格一起淡出。存在 AnimationPlayer、动作名或成功返回值，都不能单独证明动作可用。

外观真实通常同时依赖轮廓、比例、材质、光照和动作。避免只加多边形、把棱角改圆或提高曝光，就宣称完成真实化。

## 植被与细碎几何

按地形采样树根高度，树干与树冠分别选择碰撞策略，预留道路/桥口和角色转弯净空。相同网格可按空间区域批量实例化；整个地图合成一个大批次会损失有效裁剪。

叶片的全局减面和自动 LOD 容易删除大量小片，出现近景尚可、远处树冠像枯枝的问题。观察轮廓、叶片覆盖率、透明边缘和阴影；为植被单独调整 LOD 误差、透明裁切和批次范围。不要只根据三角面计数验收，也不要为全部物体关闭 LOD。

优化新资产应保留所需外观，原始输入留作可复现来源。模型变体要区分“同网格缩放/换色”和“新增原始模型”，避免夸大素材种类。
